# `<json-form>`: a settings form built from a config schema (code repo)

Written from the browser repo (`browser/plans/2026-10-14-json-form-for-code-repo.md`)
for this repo; this is its copy, kept up to date here (AGENTS.md §5.3). Work
is on the `json-form` branch: worktrees `code/json-form` and
`code-tests/json-form` (tests run with `APP_DIR=../../code/json-form`).

## Why

The browser (openp41ge explorer) gives every extension with settings a
settings page with two views of the same values, as the code editor's
workspace editor has (a form view and a JSON view):

- **JSON view:** done, with the code editor's `<json-editor>`, copied into the
  browser as a built bundle (`browser/scripts/update-uikit`,
  `browser/third_party/openp41ge-uikit/`).
- **Form view:** needs a **generic form built from a JSON Schema**. None exists:
  the workspace editor's UI view (`packages/openp41ge-extension-workspaces/src/workspace-editor.ts`,
  `renderUiView`) is written by hand for its own fields.

The user decided (2026-10-14) that the form belongs in the code repo's UI kit,
`openp41ge-sdk-uikit`, next to `<json-editor>`, so both apps use one
component: the browser for extension settings, the code editor for its own
extension config (AGENTS.md §2.9, "Settings / configuration overrides") if
the user wants it there too. Moving the UI kit to a repo of its own is
deferred; the browser copies a built bundle until then.

## What exists to build on

- `packages/openp41ge-sdk-uikit/src/json-editor/`: `<json-editor>` (Lit,
  `@customElement`, decorators), its pure helpers in `json-tree.ts`
  (`mergeDefaults`, `stripDefaults`, `pinnedPaths`, `setAt`, `cloneDeep`,
  `sortJsonKeys`, …), schema lookup in `json-tooltip.ts` (`schemaAtPath`,
  `schemaDescription`), Markdown for descriptions in `md-render.ts`
  (`renderMarkdown`). Its public API and how it shows defaults (faded,
  `explicitPaths` for values pinned equal to their default) are the model to
  follow.
- `packages/openp41ge-sdk-uikit/src/components/openp41ge-toggle.ts`:
  `<openp41ge-toggle>`, the settings switch (use it for booleans).
- `packages/openp41ge-sdk/src/config.ts`: the config contract
  (`ConfigSchema`, `configDefaults`, `configErrors`, `mergeConfig`,
  `validateConfigSchema`). The UI kit doesn't depend on `openp41ge-sdk`
  (see its `package.json`): the form takes `defaults` and `errors` from its
  host, as `<json-editor>` takes `defaults`, rather than importing the
  config logic. If the agent finds it needs `ConfigSchema`'s type, a local
  structural type (as `<json-editor>`'s `schema: unknown`) is the pattern;
  ask before adding a dependency.
- `packages/openp41ge/src/renderer/components/openp41ge-config-editor.ts`:
  the code editor's JSON settings tab (staged edits, Save, Reset, "Show
  default values"); a host the form could join (open question 2).
- The package's build: `vite.config.ts` (one `lib.entry` per subpath) and
  `package.json` `exports`; `lit` is external.

## The component

**Where:** `packages/openp41ge-sdk-uikit/src/json-form/` (`json-form.ts`,
the element; `form-model.ts`, pure schema-to-fields logic; `index.ts`,
exports), a `json-form` entry in `vite.config.ts`, and an
`"./json-form"` export in `package.json`, as `json-editor` has.

**API** (names are contracts: confirm them with the user, AGENTS.md §5.1):

- `<json-form>`, class `JsonFormElement`.
- Properties:
  - `schema`: the config's JSON Schema (an object schema at the root).
  - `value`: the **user's values only** (what's stored), as `<json-editor>`'s
    host passes overrides.
  - `defaults`: the schema's defaults (the host computes them with
    `configDefaults`).
  - `errors`: problems to show beside fields, as `[{ path, message }]` (the
    host checks with `configErrors`; messages start with their path, e.g.
    `size: must be at least 1`).
  - `readonly`.
- Event `json-form-change` (exported constant `JSON_FORM_CHANGE`), detail
  `{ value }`: the new user values after each edit. Bubbles, composed (as
  `json-editor-change`).
- Same theming as `<json-editor>`: CSS custom properties only
  (`--bg-primary`, `--bg-secondary`, `--text-primary`, `--text-secondary`,
  `--accent`, `--border-color`, `--divider`, `--font-ui`, `--font-mono`; add
  `--jf-*` where it needs its own), no Tailwind, no Electron or Node APIs, no
  app imports: the browser bundles it from source with Vite and runs it in a
  plain web page.

**Fields**, one per property, in schema order, from the property's schema:

| Schema                                                                                     | Field                                                                        |
| ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| `boolean`                                                                                  | `<openp41ge-toggle>`                                                         |
| `number` / `integer`                                                                       | number input; `minimum` / `maximum` as its bounds; step 1 for `integer`      |
| `enum` (any type)                                                                          | a menu of the values                                                         |
| `string`                                                                                   | text input; **`"secret": true`**: a masked (password) input                  |
| `array` of strings / numbers / booleans / enums                                            | a list: add, remove, edit items                                              |
| `array` of objects                                                                         | a list of groups, each as below                                              |
| `object` with `properties`                                                                 | a group of fields (nested, with its own heading)                             |
| anything else (type unions, `additionalProperties`-only maps, arrays of arrays, no `type`) | a note: "Edit this in the JSON view", with its current value shown read-only |

- **Label** from `title`, else the key; **description** under it, rendered
  with `renderMarkdown` (as the JSON editor's tooltips).
- **Defaults:** a field the user hasn't set shows its default, faded (as
  `showDefaults` does in `<json-editor>`). Editing sets it. Each set field has
  **Reset**, which removes the user's value (the default applies again).
  Setting a value equal to its default keeps it set (a pinned value, as
  `explicitPaths`), so Reset still shows.
- **User-provided** settings (no `default`): empty, with a "Not set" hint;
  ones in `required` are marked **Required** and come first.
- **Errors** (`errors`) show under their field, and a field whose stored value
  doesn't fit shows that value with its error, not the default.
- **Edits** emit `json-form-change` with the full user values (a cleared,
  user-provided field removes its key). The form never validates or saves:
  the host does (both hosts already stage edits and save on Save / Cmd-S).
- Keyboard and screen reader: real `<label for>`s, native inputs, a group
  per object (`<fieldset>`/`<legend>`), Reset buttons named "Reset
  <label>".

`form-model.ts` (pure, unit-tested) turns `(schema, value, defaults,
errors)` into field descriptors (kind, path, label, description, shown value,
set or default, required, error); `json-form.ts` only renders them and turns
input into new values.

## Tests (code-tests, `packages/openp41ge-sdk-uikit/test/json-form/`)

Test-first, as AGENTS.md §5.6 says; the json-editor tests there
(`test/json-editor/*.test.ts`, vitest, mounted elements) are the pattern.

- **Unit** (`form-model`): each schema kind to its field kind; unsupported
  shapes to the JSON-view note; schema order with required-unset first;
  defaults shown when unset, values when set, pinned values set; nested
  objects and arrays of objects; errors attached by path.
- **Component:** renders a field per property; editing each kind emits the
  right `json-form-change` value; Reset removes the key; secret inputs are
  masked; number bounds; `readonly` stops edits; an error shows under its
  field.

## Decisions (the user, 2026-10-14)

1. **Stories:** yes, `json-form.stories.ts` beside the component.
2. **The code editor too:** yes — `openp41ge-config-editor` (the settings
   tab) gets a Form/JSON switch, as the workspace editor has.
3. **Arrays of objects:** full editing (add, remove, reorder), in the
   workspace editor's accordion/card style (its repository cards). A first
   version to improve on.
4. **Names:** as proposed — `<json-form>`, `JsonFormElement`,
   `json-form-change` / `JSON_FORM_CHANGE`, `errors: [{ path, message }]`, the
   `./json-form` subpath.

kit (`./json-form` export, build entry, a shared extension-runtime
specifier), `json-form.stories.ts`, a `disabled` property on

Checked in the dev app (the Agents settings) and a Storybook build.

Left:

- **Maps** (agreed, built): an object with an `additionalProperties` schema and no
  `properties` is a keyed card, one segment per entry titled by its key,
  with add (asks for the key), rename and remove; its values edit by their
  schema (objects open to their fields; maps nest).
- **`x-keysOf`** (agreed name, built): `{ "x-keysOf": "<sibling map>" }` on a
  string makes it a menu of that map's keys; the map's card marks the entry
  it names (Default) with a Make default action. The host's validation
  refuses a value that is not one of the keys.
- **Agents schema** (agreed, built): `providerId` is `defaultProviderId`
  (with a data migration); short descriptions, titles, a masked API key.
  The map card shows a map's defaults merged with the user's values (as the
  platform merges them); an entry from the defaults cannot be removed or
  renamed (it would come back). The Settings tab checks the merged values.
